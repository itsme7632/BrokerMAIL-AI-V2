CONTEXT

We identified a critical false-bounce bug in the bounce scanner.

CURRENT STATUS

The bug is NOT SMTP related.

Emails are being:

✓ Sent successfully
✓ Accepted by SMTP
✓ Received in Gmail inbox
✓ Opened multiple times (tracking events recorded)

BUT

The bounce scanner later changes the same email status to:

status = "bounced"

with a permanent delivery failure.

This is incorrect.

ROOT CAUSE FOUND

In bounce-scanner.ts:

Current matching logic is performed using recipient email address + status='success'.

The scanner does NOT:

* correlate SMTP Message-ID
* correlate trackingId
* correlate draftId
* correlate emailQueue row precisely

It also does NOT check whether:

* email has open events
* email has tracking events
* email was already opened
* email was already confirmed delivered

before overwriting status.

Because of this:

A bounce email for [recipient@example.com](mailto:recipient@example.com) can incorrectly mark an unrelated previously delivered email to the same recipient as bounced.

* matching query has NO orderBy()
* matching query can select arbitrary success records
* emails with open tracking events are being overwritten as bounced
