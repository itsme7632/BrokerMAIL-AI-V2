--------------------------------------------------
FIX A — Clear mailbox quota state when the LAST campaign ends
--------------------------------------------------

Current issue:

If a campaign finishes or is cancelled while the mailbox is in quota recovery, the mailbox may remain permanently stuck showing:

- Cooling Down
- Retrying
- Last Error
- Probe Count
- Cooldown Timer

even though there are no active campaigns.

Reason:

mailboxes.quota_* fields are only cleared by:

1. a future successful send
2. the in-memory recovery loop

Neither is guaranteed after the last campaign ends.

Implement:

Whenever a campaign transitions to:

- completed
- cancelled
- failed

check whether there are ANY remaining active or paused campaigns for the same mailbox/user.

If NONE remain:

Immediately clear ALL mailbox quota state:

quota_status
quota_reached_at
quota_cooldown_until
quota_smtp_response
quota_probe_count

The mailbox should instantly become READY.

Do NOT wait for another probe.
Do NOT wait for another send.
Do NOT rely on the recovery loop.

--------------------------------------------------
FIX B — Clean up stale deferred queue
--------------------------------------------------

Current issue:

The Mailbox page still shows:

Retry Queue: X
Deferred: X

even after the campaign finished hours ago.

Reason:

email_queue rows remain with:

status='deferred'

forever.

The API simply counts every deferred row.

Implement:

Whenever the LAST campaign finishes or is cancelled:

Find every deferred email_queue row belonging to that campaign.

Those rows must no longer remain in retry state.

Update them to the appropriate terminal state.

Also clear:

deferred_count
retry_after
last_error

where appropriate.

The Mailbox page should immediately show:

Retry Queue = 0
Deferred = 0

if no retryable work actually exists.

Do NOT delete historical email records.

Preserve reporting/history.
