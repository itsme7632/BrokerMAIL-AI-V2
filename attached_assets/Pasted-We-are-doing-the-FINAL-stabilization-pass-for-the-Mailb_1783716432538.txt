PART 1 — FIX THE DEFERRED CLEANUP RACE
====================================================

Current issue:

Campaign cancellation/completion currently triggers finalizeMailboxIfNoActiveCampaigns() too early.

Flow today:

Campaign cancelled/completed
→ cleanup executes
→ SMTP worker still finishes several in-flight emails
→ processor writes new email_queue.status='deferred'
→ those rows are never cleaned

Move the cleanup to the TRUE END OF THE PROCESSOR.

Requirements:

• Cleanup must execute only after the campaign processor has completely exited.
• At that point no new deferred rows can be written.
• Do not use arbitrary delays or timeouts.
• Do not poll.
• Do not sleep.
• Hook into the processor's actual terminal lifecycle.

When the processor finishes:

1. Check whether this user still has ANY active campaign.

Active means:

pending
queued
sending
paused
cooling_down

If ANY remain:

Do nothing.

If NONE remain:

Immediately:

Clear mailbox quota fields:

quota_status
quota_reached_at
quota_cooldown_until
quota_smtp_response
quota_probe_count

Then update ONLY this campaign's email_queue rows:

status='deferred'
↓

status='failed'

Reset:

deferred_count
retry_after

DO NOT delete rows.

DO NOT remove history.

DO NOT clear last_error.

History must remain intact.
