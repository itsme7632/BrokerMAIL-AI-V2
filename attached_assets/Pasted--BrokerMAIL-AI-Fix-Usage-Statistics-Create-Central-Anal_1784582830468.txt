# BrokerMAIL AI - Fix Usage Statistics & Create Central Analytics Service

We have found several statistics bugs.

These are NOT feature requests—they are incorrect calculations and inconsistent data across the platform.

I want to fix this permanently by introducing a centralized analytics service.

==================================================
CENTRAL ANALYTICS SERVICE (REQUIRED)
==================================================

Create a single backend analytics service that becomes the ONLY source of truth for all statistics across BrokerMAIL AI.

Create:

GET /api/analytics/overview

Every page must consume this endpoint instead of calculating statistics independently.

Pages that MUST use this API:

• Dashboard
• My Profile
• Plans & Billing
• Admin Dashboard
• Future Analytics page
• Future Reports page

No duplicate calculation logic should remain in frontend components.

==================================================
GET /api/analytics/overview
==================================================

Return at minimum:

{
  totalEmailsSent,
  smtpEmailsSent,
  gmailEmailsSent,

  totalDraftsCreated,

  campaignsCreated,
  activeCampaigns,
  completedCampaigns,

  totalOpens,
  totalClicks,
  repliesReceived,

  failedEmails,
  bouncedEmails,

  connectedMailboxes,

  lastEmailSent,

  monthlyUsage,
  monthlyLimit,

  currentPlan,

  quotaRemaining,

  usageResetDate
}

If additional useful metrics already exist in the database, include them as well.

==================================================
BUG #1 — ENTERPRISE PLAN EMAILS SENT
==================================================

Problem:

Enterprise users have Unlimited email limits.

The platform currently displays:

Emails Sent = 0

because it is confusing:

Limit

with

Usage

Correct behavior:

Usage = actual emails sent

Limit = Unlimited

Example:

Emails Sent

548

∞ Unlimited

NOT

0

∞ Unlimited

Usage and Limits are completely separate values.
